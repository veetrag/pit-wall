# Play Console — Data Safety declaration

**Status:** draft for Veet to submit. I cannot and will not fill in the Console form.
**Last verified against the code:** 2026-09-19, commit d2774be

## The short version

**Pit Wall collects nothing, transmits nothing, and makes no network requests.**

This is not a claim about intent, it is a property of the binary, and two tests
enforce it:

- `tests/data/androidManifest.test.ts` asserts the merged release manifest never
  gains `android.permission.INTERNET`, and pins the complete permission set so a
  permission arriving from any dependency fails the suite.
- `tests/ui/noRemoteAssets.test.ts` asserts no shipped source references a remote
  URL.

Verified in the merged release manifest, the only two permissions are:

```
android.permission.VIBRATE
com.veetrag.pitwall.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
```

`VIBRATE` is haptic feedback. The second is generated by Capacitor for its own
internal broadcast receiver. Neither touches the network, storage outside the
app's sandbox, or any identifier.

## Answers to the form

| Question | Answer |
|---|---|
| Does your app collect or share any of the required user data types? | **No** |
| Is all of the user data collected by your app encrypted in transit? | N/A — no data leaves the device |
| Do you provide a way for users to request that their data is deleted? | N/A — no data is collected. Uninstalling removes the local save. |

Every data category — location, personal info, financial info, health, messages,
photos, audio, files, calendar, contacts, app activity, web browsing, app info
and performance, device or other IDs — is **not collected and not shared**.

### The one thing that is stored, and why it is not "collected"

The game writes a save to `SharedPreferences` (via Capacitor Preferences): the
current season, the career record, and a per-race log used to derive badges.
This is local app storage in the app's own sandbox. It is never transmitted, is
not readable by other apps, and is deleted with the app. Play's Data Safety form
covers collection and sharing — data that never leaves the device is neither.

### Advertising, analytics and purchases

None. No ad SDK, no analytics SDK, no in-app purchases, no billing library, no
account system, no login. The monetisation decision is recorded in
`docs/superpowers/specs/2026-09-19-v2-roadmap.md` §D: the game ships free with
nothing attached.

### Privacy policy

Play requires a privacy policy URL for all apps. Ours can be a single short page
stating that the app collects no data and makes no network requests — a draft is
in `docs/store/privacy-policy.md`. **You need to host it somewhere with a stable
URL** before the listing can be submitted.

## What to re-check before EVERY submission

1. Run `npx vitest run tests/data/androidManifest.test.ts` — if the permission
   set changed, this declaration is stale and must be redone.
2. Confirm no new dependency was added that bundles an SDK.

If either has changed, the answers above are no longer true.
